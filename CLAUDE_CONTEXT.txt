WHY I AM DOING THIS
--------------------------------------------------------------------

My PRIMARY goal is to LEARN programming — not to just have a finished
product. Every bug I fix, every function I write, and every design
decision I make is a learning opportunity. The finished dashboard is
secondary to the skills I build along the way.

I want to understand and apply the following programming principles
throughout this project. Keep these in mind at all times:

  SRP  — Single Responsibility Principle
         Every function and module does ONE thing only. load_data.py
         loads, clean_data.py cleans, analysis.py analyses. No mixing.

  DRY  — Don't Repeat Yourself
         If I am copy-pasting code, something is wrong. Guide me to
         extract it into a reusable function instead.

  KISS — Keep It Simple, Stupid
         Always push me toward the simplest solution that works.
         No over-engineering.

  YAGNI — You Aren't Gonna Need It
         Do not let me build features "just in case". If it is not
         needed right now, we do not build it.

  Separation of Concerns
         Data logic, UI logic, and analysis logic must stay in their
         own layers. A Streamlit page should never do raw data cleaning.

  Readability over Cleverness
         Code should be easy to read. Prefer clear variable names,
         small functions, and simple logic over "smart" one-liners.

  Defensive Programming
         Always handle edge cases — missing files, bad data, empty
         dataframes, wrong column names, etc.

  Code Conventions I follow:
         - snake_case for variables and functions
         - UPPER_CASE for constants
         - Descriptive names (not x, df2, temp)
         - Docstrings on every function (what it does, args, returns)
         - One import per line, grouped (stdlib → third-party → local)
         - Max ~80 characters per line where possible
         - No magic numbers — use named constants
